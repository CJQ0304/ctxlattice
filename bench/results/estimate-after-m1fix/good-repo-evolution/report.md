# 测量报告 · good-repo-evolution

> ⚠️ **`mode=estimate`：本报告没有精确分词器，token 数是估算的。**
>
> 具体地：`cached`（缓存命中长度）由「字符公共前缀 / chars_per_token」折算，
> 不是逐 token 比对。**δ 敏感性表在这种口径下不可用于对外结论** ——
> 它衡量的是缓存定价的影响，而缓存命中的精度正是被估算掉的那个量。
> 要出对外数字，请装 `tiktoken` 后按 `mode=exact` 重跑。

> 语料与剧本来源见文末「口径」。**本报告不含质量/保真度结论** —— 未做保真核对，
> 因此不得声称「记得一样多」，只能声称「发出的输入更少」。

**两个数必须分开读。** 输入降幅是「少发了多少」，成本降幅是「少花了多少」。
两者不等价，差额全部来自缓存定价 —— 见下面的敏感性表。

## 二、缓存敏感性（δ = 缓存单价 / 全价）

| δ | 含义 | 成本降幅 |
|---:|---|---:|
| 0.10 | 缓存九折优惠（主流 provider 常见量级） | -1.6% |
| 0.25 | 缓存七五折 | +13.7% |
| 0.50 | 缓存半价 | +20.3% |
| 1.00 | 缓存完全不计价（最悲观） | +24.0% |

> **δ=1.0 这一档是方案稳健性的下限**：它回答「即使缓存完全不省钱，本方案还省不省」。
> 若这一档转负，说明收益完全依赖缓存折扣，那是一条脆弱的结论。

## 五、口径（任何人可据此复算）

```
tokenizer      = estimate:ceil(chars/2)
mode           = estimate
transcript     = effc45511280e0e8c900c9dc6cc57f3e064e087096458384477c7a9a12fc1293
delta (δ)      = 0.100
price (p)      = 1.000
budget_tokens  = 8000
compact_interval (N) = 12 / verbatim_keep (K) = 6
high_water     = 0.75
```

计费三层：`gross = token(payload)`，`cached = 与上一轮逐 token 相同的前缀长度`，
`billable = gross − cached`，`cost_eq = billable·p + cached·p·δ`。

**语料 / 剧本 / 结果 三者的来源必须分开看：**

| 项 | 取值 |
|---|---|
| 语料 | 围绕同一个仓库连续 40 轮开发，多轮回头引用早前决定（第 12、27、32、37 轮明确回访第 3、5、12、26 轮的结论） |
| 语料来源 | 94233 = context-lattice v1.2.2 交付包 14 个文本文件的总 token（o200k_base），取自该项目 REPORT-realworld.md 的层 A 口径；此处列出的是与本剧本最相关的 6 个，分母仍按 14 文件算 |
| 剧本来源 | scripted-from-real-worklog |
| 剧本依据 | 按 2026-10 期间该仓库的真实改动与争论顺序编排；用户侧措辞据 .workbuddy/memory 下的工作日志与项目决策记录重写；助手回复为等长改写，非逐字转录 |
| 结果 | 离线回放（确定性 mock 回复），**不是生产实测** |
