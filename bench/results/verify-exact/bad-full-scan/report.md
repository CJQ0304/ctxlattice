**两个数必须分开读。** 输入降幅是「少发了多少」，成本降幅是「少花了多少」。
两者不等价，差额全部来自缓存定价 —— 见下面的敏感性表。

## 二、缓存敏感性（δ = 缓存单价 / 全价）

| δ | 含义 | 成本降幅 |
|---:|---|---:|
| 0.10 | 缓存九折优惠（主流 provider 常见量级） | -6.8% |
| 0.25 | 缓存七五折 | +2.3% |
| 0.50 | 缓存半价 | +7.1% |
| 1.00 | 缓存完全不计价（最悲观） | +10.1% |

> **δ=1.0 这一档是方案稳健性的下限**：它回答「即使缓存完全不省钱，本方案还省不省」。
> 若这一档转负，说明收益完全依赖缓存折扣，那是一条脆弱的结论。

## 五、口径（任何人可据此复算）

```
tokenizer      = tiktoken:o200k_base:2024-07
mode           = exact
transcript     = cd2dd5ee08df67d0eba1375f2ff598e614db08575e0c0907372cb1ad428049c8
delta (δ)      = 0.100
price (p)      = 1.000
budget_tokens  = 8000
compact_interval (N) = 12 / verbatim_keep (K) = 6
high_water     = 0.75
```

计费三层：`gross = token(payload)`，`cached = 与上一轮逐 token 相同的前缀长度`，
`billable = gross − cached`，`cost_eq = billable·p + cached·p·δ`。

**语料 / 剧本 / 结果 三者的来源必须分开看：**

| 项 | 取值 |
|---|---|
| 语料 | 20 轮全量审计：每轮都要求「逐条」「全量」「是否一致」「还有哪些」，工作集天然接近全部素材 |
| 语料来源 | 与 good 档同一分母，保证两档可比 |
| 剧本来源 | scripted-from-real-worklog |
| 剧本依据 | 取自该仓库真实做过的审计轮次：不变量逐条对齐、分支兜底排查、指纹碰撞排查、模板与格式文档对齐、存储迁移的隐式假设盘点 |
| 结果 | 离线回放（确定性 mock 回复），**不是生产实测** |

## 六、这份报告不能声称什么

- 不能声称「质量打平」—— 没做保真核对。
- 不能声称「生产环境实测」—— 回复是回放的，不是模型生成的。
- 不能把「输入降幅」当「省钱」直接对外说 —— 必须带 δ 与成本降幅。
