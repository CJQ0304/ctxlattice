# 测量规范（MEASUREMENT-SPEC）

> 本文由研发部主理人定义，是**验收口径**，不是实现说明。实现可以变，口径不能变。
> 核心要求来自需求方原话：**「能够真实测量实际应用中能节省多少比例的 token」**。

## 1. 要回答的问题只有一个

把上下文管理从「每轮重发全量历史」换成「由存储装配」之后：

> 在**同一份对话、同一个模型、同一套预算**下，**每轮实际发出的输入 token 降低了百分之多少**，
> 以及**扣除缓存折扣后的等效成本降低了百分之多少**。

两个数必须**分开报**，且同时报。只报前者是虚报（少发不等于少花钱），只报后者不可核对。

## 2. 两臂定义（唯一变量）

| | A 臂 · Baseline | B 臂 · Lattice |
|---|---|---|
| 上下文管理 | 调用方标准做法：`messages` 累积全量历史，每轮整包重发 | SDK 装配：`[S]静态 system + [F]冻结块 + [R] 自上一压缩边界起累积的原文轮 + [U]本轮` |
| 模型 | 完全相同 | 完全相同 |
| 系统提示 | 完全相同 | 完全相同 |
| transcript | 完全相同（同一文件、同一哈希） | 完全相同 |
| 预算 | 相同 `budget` | 相同 `budget` |

**除上下文装配方式外，不允许有任何差异。** bench 必须能证明这一点：两臂的 payload 差异只允许出现在"历史部分被替换"这一处，`system` 首段逐字节相同。

> **关于 `K` 的口径澄清（2026-10-28 主理人确认）**：`K` 是**压缩边界时的段起点参数**，
> **不是每轮滑动的窗口宽度**。边界内 R 段**只许在尾部追加**，绝不左移。
> 若按字面实现成"每轮取最近 K 轮"，第 t 轮与第 t−1 轮在 R 段起点即分叉，
> `cached_i` 退化为 `count(S)`，**每一轮都变成全价轮**，B 臂在两项指标上同时输给 A 臂，
> 而且**没有任何报错**。这条不是实现细节，是方案成立的前提，验收必须逐字节断言。

## 3. 计费口径（三层，逐层严格）

对第 `i` 轮：

```
gross_input_i   = token(payload_i)                    # 实际发送的输入 token 总数
cached_i        = 与 payload_{i-1} 的公共前缀 token 数   # 逐 token 相同才算命中
billable_i      = gross_input_i − cached_i             # 按全价计的部分
cost_eq_i       = billable_i × p + cached_i × p × δ    # δ = 缓存折扣系数
```

- `δ` 与 `p` 是**参数**，不是结论。默认取 `δ = 0.1`（90% 折扣）与 `p = 1.0`（归一化单价），
  **报告必须打印本次使用的 δ/p**，并附一张 `δ ∈ {0.1, 0.25, 0.5, 1.0}` 的敏感性表。
  理由：不同 provider 的缓存折扣差一个量级，结论不能绑死在某一家上。
- **压缩边界轮单独标记**。边界那一轮前缀被重写、缓存必然失效，`cached_i ≈ 0`。
  这是本方案的**已知成本**，必须计入，不许摊平、不许略过。
- 累计口径：`Σ gross`、`Σ cost_eq`，以及**回本点** `i*` = 首个使 `Σ_{1..i}(cost_eq_A − cost_eq_B) > 0` 的轮次。
  回本点为 `null`（跑到最后仍未回本）时**照实写 null**，不许用"趋势向好"替代。

## 4. token 计数必须可复现

- **计数源**：`tiktoken` 的 `o200k_base`（OpenAI 族），版本**钉死并写进报告**；
  若目标模型是 Claude 族，主表仍用 `o200k_base` 以便跨实验可比，另附一列说明"Claude 分词不同，比例结论不受影响、绝对值不可直接引用"。
- **不允许多数估算**：禁止 `len(text)/4` 这类经验换算进入主表。可以作为"未安装 tokenizer"的降级路径存在，但报告必须显式标注 `MODE=estimate` 且结论降级为"量级判断"。
- **transcript 必须有哈希**：`sha256` 写进报告，任何人可复算。
- **随机性为零**：离线臂用 deterministic mock 模型（固定回复），保证两次运行逐字节相同。实跑（live）另开一节，不与离线结果混表。

## 5. 语料与剧本的来源必须分开标注

这是最容易糊弄过去的地方，所以单独成条：

| 项 | 允许的取值 | 报告里怎么写 |
|---|---|---|
| 语料（被压的素材） | 真实文件 / 合成 | 写清路径与总 token |
| 剧本（对话怎么走） | **真实采集** / 按真实工作形态编排 | 写清是哪种；编排的必须说明编排依据 |
| 结果 | 实跑 / 离线回放 | 写清 |

**"真实测量"= 语料真实 + 剧本有据 + 计数精确 + 缓存计入。** 四缺一就只能叫"模拟测算"，报告标题必须改。

## 6. 反例集是方法有效性的自检

bench 必须包含一档 **bad-locality** transcript：每轮的工作集都接近全量（例如"逐条核对全部字段"这类任务）。
**如果它在 B 臂上不出现明显衰减（甚至负收益），说明测量方法有偏**，先修方法再改结论。

同时必须有 **no-locality-at-all**：一轮就结束的短会话。它应当显示 B 臂**更贵**（冻结块是净开销）。
这两档是"我们没在挑有利场景"的证据，写报告时必须带上。

## 7. 输出物（固定形状）

```
bench/results/<yyyy-mm-dd>-<label>/
  report.md        # 人读：结论 + 口径 + 敏感性表 + 反例
  turns.csv        # 逐轮：arm,turn,gross,cached,billable,cost_eq,boundary
  summary.json     # 机器读：input_saving_pct, cost_saving_pct, break_even_turn,
                   #          delta_used, price_used, tokenizer, transcript_sha256, mode
```

`summary.json` 的字段名固定，供 CI 与外部比对。改字段名 = 改口径 = 需要重新评审。

## 8. 明确不允许声称的结论

1. 不许把"少发了 token"直接说成"省了钱"（不含缓存项时）；
2. 不许把离线回放的数字说成"生产环境实测"；
3. 不许只报省钱那一档 transcript，不报反例；
4. 不许在 `mode=estimate` 时报出两位小数的百分比（精度撑不住）；
5. 不许把"质量打平"当结论 —— 除非做了保真度核对并在报告里给出核对方法。
